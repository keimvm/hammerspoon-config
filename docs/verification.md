# 検証手順

変更後に行う確認の手順です。自動検証（Automated Verification）で設定とロジックを確かめ、実機確認（Manual Runtime Verification）で Hammerspoon と macOS 上の動作を確かめます。自動検証が通っても、実機確認が済んだことにはなりません。

## 自動検証

`lua` と `luac` が必要です（`brew install lua`）。リポジトリのルートで次を実行します。

```sh
./scripts/check
git diff --check
```

`./scripts/check` は Lua の構文、`init.lua`・`config.lua`・`modules/*.lua` が Git で追跡されていること、fake `hs` による挙動のテスト（`tests/*_test.lua` のすべて）を確かめます。Hammerspoon には接続せず、実際のキー変換やアプリ操作は行いません。`git diff --check` は差分の空白の誤りなどを確かめます。

1つのテストファイルだけを実行するときは `lua tests/run.lua tests/hotkeys_test.lua` のように指定します。

[init_test.lua](../tests/init_test.lua) は、同梱の `config.lua` の割り当て（Hotkey の件数や `⌃G` が Google Chrome であることなど）を確かめます。`config.lua` の割り当てを変えたら、このテストも合わせて更新してください。

## 実機確認

自動検証が通ったら、変更した機能と、その影響を受ける機能の項目を実施します。文書だけの変更では、リンク先と記載内容が実装と合っているかを確かめます。

最初に Hammerspoon のメニューから **Reload Config** を実行し、エラーの表示がないことを確認します。以下は [config.lua](../config.lua) の初期設定を前提としています。割り当てを変更している場合は読み替えてください。一時的に変更する値は控えておき、検証後に元へ戻します。

### Config Preflight と Safe Reload

- [ ] `config.lua` の空白だけを変えて保存すると、何も表示されない。
- [ ] `{ "ctrl+m", app = "Typora" }` を `{ "ctrl+m", app = "Typora", onyl = "Finder" }` に変えて保存すると、「設定に問題があるため再読み込みしませんでした（今の設定のまま動いています）」と `hotkeys[8].onyl: 不明な項目です（もしかして only）` が表示され、`⌃M` が引き続き動く。
- [ ] 表示は画面をクリックすると消え、クリック先も通常どおり反応する。Console に同じ内容が残っている。
- [ ] 元に戻して保存すると「設定を再読み込みしました（Hotkey 18 件）」と表示される。
- [ ] 問題のある状態のまま Hammerspoon を再起動すると「設定に問題があるため、何も適用していません」と表示され、直して保存すると適用される。
- [ ] `hotkeys` を一時的に `(function() local t = {}; t[2] = { "ctrl+j", send = "left" }; t[4] = { "ctrl+l", send = "right" }; return t end)()` に変えて保存すると、リスト形式の問題が表示され、変更前の Hotkey が引き続き動く。確認後は元に戻す。

### Input Remap

- [ ] `hidutil property --get 'UserKeyMapping'` に `caps_lock` → `left_control`、`left_control` → `left_command`、`left_command` → `eisu`、`right_command` → `kana` の4つの変換がある。
- [ ] 物理 `left_control` を Command キーとして使える。
- [ ] 物理の左 Command で英数、右 Command でかなに切り替わる。
- [ ] コマンドパレットの「キー変換を一時解除」で `UserKeyMapping` が空になり、再読み込みで戻る。
- [ ] しばらく操作しなかった後に打ち始めても、最初の打鍵が遅れない。

### Hotkey

- [ ] 物理 `caps_lock+i/j/k/l` がそれぞれ `up/left/down/right` として動き、長押しで繰り返し入力になる。
- [ ] 物理 `caps_lock+h/d` が後方削除・前方削除として動き、長押しで繰り返し入力になる。
- [ ] `F5` が最前面アプリへ `⌘R` を一度だけ送り、長押ししても繰り返さない。
- [ ] Google Chrome が最前面の間は `⌘D` でブックマーク追加が開かない。
- [ ] Google Chrome 以外では、`⌘D` がそのアプリ本来の操作として動く。
- [ ] テンキーがある環境で `{ "ctrl+pad+", send = "pad+", once = true }` を一時的に追加すると、検証を通り、テキスト入力欄で `⌃` とテンキーの `+` を押すと `+` が1文字入力される。確認後は追加した行を削除する。

### App Switcher

- [ ] 対象アプリが未起動なら、その Hotkey で起動する。
- [ ] Finder のウィンドウをすべて閉じ、Finder が最前面の状態でも Hotkey で新しいウィンドウが開く。
- [ ] 現在の Space の対象ウィンドウが最前面で同じ Hotkey を1回押すと、別の Space のウィンドウも含めてアプリ全体を非表示にする。
- [ ] Space 1 と Space 2 に対象ウィンドウを用意し、アプリが最前面でない状態から各 Space で Hotkey を押すと、同じ Space のウィンドウにフォーカスする。
- [ ] 現在の Space に Google Chrome のウィンドウを3つ用意する。3つ目をクリックしてから別のアプリへ移り、Hotkey を押すと3つ目に戻る。何度繰り返しても同じウィンドウに戻る。
- [ ] 上の状態で Hotkey を1回押して隠し、もう一度押すと、隠す前に使っていたウィンドウに戻る。Dock Toggle や `⌘H` で隠した場合も同じ。
- [ ] Chrome が最前面のときに Hotkey を素早く2回押すと、隠れずに次のウィンドウへ切り替わる。続けて押すたびに、3つのウィンドウを順に巡回する。
- [ ] 1回押してから隠れるまでの待ち時間が気にならない。ウィンドウが1つしかないアプリ（例: Typora、Zed）では、待たずにすぐ隠れる。
- [ ] Chrome のウィンドウの1つを最小化して別のアプリへ移り、Hotkey を押すと、最小化したウィンドウは元に戻らず、表示中のウィンドウが前面に出る。2回押しの巡回でも最小化したウィンドウは飛ばす。
- [ ] Chrome が最前面のときに Chrome の Hotkey を押し、0.3 秒以内に別アプリの Hotkey を押すと、Chrome が隠れてから別アプリへ切り替わる。
- [ ] 現在の Space の対象ウィンドウが最小化されている場合、別の Space のウィンドウより優先して復帰する。
- [ ] 現在の Space に対象ウィンドウがない場合は、別の Space のウィンドウへ移動する。
- [ ] Finder のデスクトップだけが最前面で、対象ウィンドウは別 Space にだけある場合も、1回の Hotkey でそちらへ移動する。
- [ ] cmux などで補助要素がウィンドウ一覧に含まれていても、別 Space の実際のウィンドウへ移動する。
- [ ] 複数のディスプレイでは、各ディスプレイで現在表示中の Space にあるウィンドウを優先する。

### Finder Cut

検証用のフォルダを2つ用意し、片方にテスト用のファイルを置いて行います。

- [ ] ファイルを選んで `⌘X` を押し、もう一方のフォルダで `⌘V` を押すと、ファイルが移動する（元のフォルダから消える）。複数のファイルでも同じ。
- [ ] 移動の後にもう一度 `⌘V` を押しても、移動したファイルが重複して作られない（通常の貼り付けとして扱われる）。
- [ ] `⌘X` の後に別のファイルを `⌘C` でコピーし、`⌘V` を押すと、後からコピーしたファイルがコピーされ、どちらのファイルも移動しない。
- [ ] `⌘X` の後に別のアプリで文字をコピーし、Finder で `⌘V` を押しても、ファイルは移動しない。
- [ ] `⌘C` → `⌘V` は、これまでどおりコピーになる。
- [ ] ファイル名の変更中に名前の一部を選んで `⌘X` → `⌘V` すると、文字が切り取られて貼り付けられる。検索欄と「フォルダへ移動」（`⇧⌘G`）の入力欄でも同じ。
- [ ] Finder 以外のアプリ（テキストエディットなど）では、`⌘X` / `⌘V` がこれまでどおり動く。
- [ ] 何も選ばずに `⌘X` を押してから `⌘V` を押しても、エラーや意図しない移動が起きない。

### Input Source

- [ ] Zed、cmux、Visual Studio Code をそれぞれ最前面にすると、英数に切り替わる。
- [ ] Typora や Notion など対象外のアプリでは、現在の入力ソースを維持する。

### Dock Toggle

- [ ] 最前面でないアプリの Dock アイコンをクリックすると、そのアプリが前面に出る。
- [ ] もう一度クリックすると、アプリ全体が非表示になる。さらにクリックすると再表示される。
- [ ] Visual Studio Code でも同じように動く（Dock の表示名とアプリ名が違うアプリ）。
- [ ] Finder のウィンドウをすべて閉じ、Finder が最前面の状態で Finder のアイコンをクリックすると、新しいウィンドウが開く。
- [ ] ウィンドウをすべて最小化したアプリのアイコンをクリックすると、隠さずに元に戻す。
- [ ] Command + クリックで Finder に表示される。右クリックと Control + クリックでメニューが出る。
- [ ] ウィンドウ内やメニューバーのクリックがこれまでどおり反応し、遅れを感じない。
- [ ] 検証用アプリの PID を確認し、ターミナルで `sleep 5; kill -STOP <PID>` を実行して、5秒以内にそのアプリを前面にする。一時停止後にそのアプリの Dock アイコンをクリックしても、Hammerspoon の Hotkey や他のクリックが長く待たされず、アプリを隠さない。確認後はターミナルから `kill -CONT <PID>` で再開し、前面に戻してから再びアイコンをクリックすると隠せる。
- [ ] ターミナルで `killall Dock` を実行した後も、もう一度クリックで隠せる。
- [ ] Dock を自動的に隠す設定や、画面の左右に置いた場合も動く。
- [ ] フルスクリーンのアプリで画面下端をクリックしても、アプリが隠れない。

### タイマー

- [ ] `⌃P` で入力画面が開き、入力欄の案内が「分（1〜180）」になる。
- [ ] `25` と入力して Enter を押すと、メニューバーに `25:00` が出て減っていく。
- [ ] 入力中の `Tab` で数値を保ったまま「秒（1〜10800）」へ切り替わり、もう一度押すと分へ戻る。
- [ ] `1.5` は `15` に変換されず、「数字と s / m だけ入力してください」と表示される。
- [ ] `181` 分、または秒へ切り替えた `10801` では許容範囲が表示され、タイマーは開始しない。
- [ ] メニューバーをクリックして「キャンセル」を選ぶと停止し、通知は出ない。
- [ ] 期限に達するとメニューバーが消え、短い完了音が1回だけ鳴り、「○分が経過しました」（秒指定なら「○秒が経過しました」）と表示される。表示は画面をクリックすると消える。

### コマンドパレット

- [ ] `⌃;` でパレットが開き、各行に `⌃I` や `⌘D · Google Chrome のみ` のような Hotkey が表示される。
- [ ] 「Chrome」と入力すると、Google Chrome に関係する行に絞り込まれる。
- [ ] 「Typora に切り替え」を選ぶと、パレットが閉じてから Typora に切り替わる。
- [ ] 「↑ を送る」を選ぶと、元のアプリでカーソルが上へ動く。
- [ ] タイマーの実行中は「タイマーを停止」が残り時間とともに並び、選ぶと止まる。
- [ ] もう一度 `⌃;` を押すとパレットが閉じる。

## 失敗した場合

意図しない挙動があれば、変更を修正または取り消してから、自動検証と対象項目の実機確認をやり直します。報告時は自動検証と実機確認の結果を分け、未確認の項目があれば明記してください。

物理キーの変換で操作が難しくなった場合は、[README の「キー配置を元に戻したい」](../README.md#キー配置を元に戻したい) に沿って変換を解除してから、設定を直します。
