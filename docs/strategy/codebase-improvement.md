## 全面書き直し（2026-10-18）

過去の設計から価値観だけを残し、設定の書き方、モジュール構成、テストを作り直しました。

### 引き継いだ価値観

- 入力操作を壊さない。設定の不備で一部だけが適用される状態を作らないよう、副作用より前に Config Preflight を行い、問題は項目の場所とともにまとめて報告する。
- 入力遅延を生まない。keyDown を常時監視する eventtap は使わず、物理キーの変換は hidutil に任せる。常駐する eventtap は、クリックで閉じる表示のためにマウスの押下だけを見るものに限る。
- 設定と実装を分ける。設定は1か所にまとめ、適用の順序は `init.lua` に明示する。
- 自動検証と実機確認を分け、報告でも区別する。
- 必要になるまで抽象化せず、使っていない機能は残さない。
- App Switcher の Space と Finder に関する挙動は実機検証の積み重ねなので、テストごと引き継ぐ。

### 設計判断

1. **設定を `config.lua` に分離した。** Safe Reload で設定だけを読み直して検証するため。`init.lua` は起動の順序だけを持つ。
2. **Hotkey を1つのリストにまとめた。** 以前は Control Layer、App Switcher、App Hotkey Blocker、Timer などに分かれ、Hotkey Identity の重複は機能を横断して検証していた。1つのリストにすると、どのキーが何をするかを1か所で読め、重複の検出も単純になる。組み合わせは `"ctrl+i"` のような Chord で書く。
3. **App Hotkey Blocker を Scope に一般化した。** 「特定のアプリが最前面の間だけ有効」は無効化以外の動作にも使えるため、`only` / `except` としてすべての Hotkey に持たせた。範囲が重ならない同じ組み合わせは許可し、アプリごとの使い分けを可能にした。切り替えの際は先に無効化してから有効化し、同じ組み合わせが同時に有効にならないようにする。
4. **最前面アプリの監視を1つにした。** 以前は App Hotkey Blocker と App Input Source がそれぞれ application watcher を作っていた。
5. **Safe Reload を加えた。** `config.lua` を保存すると Config Preflight を行い、通った場合だけ再読み込みする。通らなければ今の状態を保つ。起動時に設定の不備で何も適用しなかった場合も監視だけは始め、直して保存すれば復旧できるようにした。ファイルの監視は入力に影響しないため、「不備があれば副作用を起こさない」の例外として扱う。
6. **Hotkey の登録失敗は残りを登録して報告する。** 以前は最初の失敗で止まっていたが、その時点で一部は登録済みだった。他のアプリが確保したキーなど環境による失敗は Config Preflight で防げないため、すべて試してから報告する。
7. **問題の表示を日本語にし、打ち間違いの候補を添える。** Console を開かなくても画面の表示だけで直せるようにするため。
8. **remap を `物理キー = "変換後のキー"` の形にした。** 変換元の重複は構造上書けず、変換の順序は意味を持たないため。
9. **コマンドパレットを加えた。** 一覧を設定から作るため、Hotkey の早見表が設定とずれない。

### 削除したもの

| 対象 | 理由 |
| --- | --- |
| Command 単体押し（`commandKeys`） | 常時の keyDown 監視で打ち始めが遅れるため無効化されていた。hidutil による英数・かな変換で代替済み |
| Unicode Converter | 無効化されたまま使われていなかった |
| `sentinelCommand`、`ignoredEventSourceUserData` | 設定にも文書にもない未使用の機能 |
| Hotkey と機能ごとの `enabled` | 無効にするには行を消すかコメントアウトする。無効な項目のための検証規則も不要になった |
| `bindings.lua`、`hotkey_registry.lua`、`config_validation.lua` | `hotkeys.lua`、`preflight.lua`、各機能の `validate` に置き換えた |

### 以前の設定との対応

| 以前（`init.lua` の `config`） | 現在（`config.lua`） |
| --- | --- |
| `hidRemap.mappings = { { from = "caps_lock", to = "left_control" } }` | `remap = { caps_lock = "left_control" }` |
| `controlLayer.bindings = { { mods = { "ctrl" }, key = "i", to = "up" } }` | `hotkeys = { { "ctrl+i", send = "up" } }` |
| `repeatable = false` | `once = true` |
| `appSwitchers = { { appName = "Zed", mods = { "ctrl" }, key = "r" } }` | `{ "ctrl+r", app = "Zed" }` |
| `appHotkeyBlockers = { { appName = "Google Chrome", mods = { "cmd" }, key = "d" } }` | `{ "cmd+d", block = true, only = "Google Chrome" }` |
| `appInputSources.bindings = { { appName = "Zed", source = "eisu" } }` | `inputSource = { eisu = { "Zed" } }` |
| `timer = { mods = { "ctrl" }, key = "p" }` | `{ "ctrl+p", run = "timer" }` |

書き直し前と同じ割り当てに加え、コマンドパレットを `⌃;` に割り当てた。

## 段階的な改善（2026-07-11）

2026-07-11 に進めた改善の目的、設計判断、完了結果です。M1〜M4 は完了済みです。ここに出てくるモジュール名や設定項目は書き直し前のものです。

### 目的と判断基準

目的は、入力操作を壊さず、安心して設定を変更できる状態にすることです。保守性、テスト、モジュール構成の整理は、そのための手段として評価します。新機能の追加速度や抽象化の統一より、変更時の回帰検出と復旧しやすさを優先します。

改善は個別の実装案を先に固定せず、目的、評価軸、優先順位を合意してから実行単位へ分ける方針としました。挙動を変える必要がある場合は、構造の整理とは別の変更として扱います。

### 設計判断（2026-07-11）

#### 自動検証と実機確認を分ける

自動検証（Automated Verification）は `luac`、Git の追跡確認、fake `hs` を使い、構文、設定、入力ロジックを再現可能な形で検証します。実機確認（Manual Runtime Verification）は、Hammerspoon と macOS 上で Hotkey、`eventtap`、`hidutil`、アプリのフォーカスなどを確認します。

当時は Hammerspoon のプロセスが起動していても CLI から IPC に接続できなかったため、IPC による再読み込みを自動検証の必須条件にしませんでした。この記録は現在の環境での接続可否を示すものではありません。

#### 設定と適用順を `init.lua` に保つ

`init.lua` は次の三段構成としました。

1. 単一の `config` テーブルに Desired Hotkey と各機能の設定を宣言する。
2. `configValidation.validate(config)` で設定全体を検証する。
3. 成功した場合だけ、各機能の適用・登録処理を明示的に呼ぶ。

設定値は `init.lua`、動作の実装は `modules/` が管理します。適用順を隠す大きな調整用モジュールは作りません。Unicode Converter の有効・無効も `config.unicodeConverter.enabled` と再読み込みで切り替え、Hotkey やメニューバーに別の状態を持たせない方針です。

#### 設定全体を副作用より前に検証する

Hotkey の登録、`eventtap` や `hidutil` の開始より前に Config Preflight を行い、設定不備によって一部の処理だけが適用される状態を防ぎます。

対象は必須項目と型、未知のキー・修飾キー、Hotkey Identity と `id` の重複、Input Remap の変換定義、有効・無効の指定です。不備は最初の1件で止めず、項目のパスとともに集約して一つのエラーにします。入力された設定データは変更せず、アプリなどの環境依存の存在確認は行いません。

#### Input Remap のモジュールを統合しない

`hid_remap`、`command_keys`、`control_layer` は、それぞれ `hidutil` のタスク、Command 単体押しの状態管理、Hotkey の登録を担当します。検証では、3モジュールをまたぐ共有状態、必須の呼び出し順、共通の後始末は確認されませんでした。

そのため、機能ごとのモジュールを維持し、共通のライフサイクル管理や、既存モジュールを順に呼ぶだけの調整用モジュールは追加しませんでした。共通化は、複数モジュールで守るべき条件が実際に確認できた場合に限ります。

#### App Switcher は既存の呼び出し口から検証する

まず既存の `toggleOrCycle` を fake `hs` 経由で検証し、不自然または過度に複雑になった場合だけ内部の分離を検討する方針としました。起動、非表示、フォーカス、ウィンドウの巡回、再表示を既存の呼び出し口から検証できたため、テストのためだけの公開メソッドや実行環境用のアダプターは追加しませんでした。

#### 改善中に維持した操作

- 物理 `caps_lock` → `left_control`、物理 `left_control` → `left_command` の変換。
- Command キーの単体押しによる英数・かなの送信。
- `ctrl+i/j/k/l` による矢印入力と、長押しの繰り返し入力。
- App Switcher の起動、フォーカス、非表示、ウィンドウの巡回。
- Unicode Converter の文字とコードポイントの相互変換。有効・無効は変更可能な設定として維持。

これは当時の維持対象です。現在の割り当ては [config.lua](../../config.lua) で確認してください。

#### M3 で解消した問題

- HID 変換を無効化しても OS に変換が残る問題は、明示的な無効化時に空の `UserKeyMapping` を適用して解消しました。
- 左右 Command の同時操作で単体押し判定の状態が残る問題は、全体の `cmd` フラグだけに依存せず、キーごとの `flagsChanged` イベントで状態を更新して解消しました。

#### M4 の当時の検証範囲

当時の `toggleOrCycle(appName, dirToOpen)` にはディレクトリを指定して起動する機能があり、失敗時に通常起動へ戻る動作も検証しました。実機の `hs.fs.dir` が利用できないディレクトリに対してエラーを返すことを確認し、実装で受け止め、fake `hs` にも同じ失敗を再現しました。

`dirToOpen` とその処理は後に削除され、現在の呼び出し口は `toggleOrCycle(appName)` です。上記は過去の検証記録であり、現在の設定項目ではありません。

### 当時の実行ルール

M1 の完了前には Input Remap や App Switcher の構造変更に着手せず、M1〜M4 を独立した単位で進めました。各段階は、自動検証、対象範囲の実機確認、意図しない挙動変更がないことを完了条件としました。

条件を満たさない場合はその段階で修正または変更を取り消し、複数段階を一つの構造変更にまとめない方針でした。次の改善は、この完了結果を基に別の計画と Issue で評価します。
